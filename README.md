## 1. 这个项目是做什么的

作品名《布上歌》：贵州惠水布依族**枫香染**纹样 × 布依族民歌**《好花红》**。

用户用手机摄像头扫描三张「纹样卡」图片，网页识别后播放对应唱段，并在屏幕下方浮现歌词：

| 纹样卡 | 唱段 | 对应音频 | 状态 |
|---|---|---|---|
| card1.png | 起 · 唱花 | assets/song_1.mp3 | 已放入 |
| card2.png | 承 · 咏情 | assets/song_2.mp3 | 已放入 |
| card3.png | 合 · 收腔 | assets/song_3.mp3 | 已放入 |

网站共三个页面：

- `index.html` —— 介绍页（作品阐述 + 两个按钮）
- `ar.html` —— AR 体验页（核心）
- `pattern.html` —— 纹样图谱页（三张卡 + 工艺说明）

**现在已经配齐**：AR 靶图文件（第 6 节）和三个唱段音频（第 7 节）都已就位，直接可以跑。若以后换纹样图，按第 6 节重新编译 `targets.mind`；若换唱段，按第 7 节重新命名三个音频。

## 2. 准备准备（第 2 节 · 准备工作）

开始前请准备好：

1. **一台电脑**（Windows 或 Mac 都可以）
2. **一部手机**（想体验 AR 才需要；只在电脑上看可以没有）
3. **电脑和手机连同一个 WiFi**（手机体验时用）
4. **三段音频文件**（你的唱段，`.mp3` 格式）
5. 本项目文件夹 `bushangge`（你已经有了）

> 提示：三张纹样卡图片（card1/2/3.png）是要**打印出来**（或显示在另一块屏幕上）给摄像头扫的。
> 建议用 A4 彩打，图案区域尽量大一点、平整不反光，识别更稳。

## 3. 安装 VS Code 和 Live Server 插件

### 3.1 安装 VS Code（免费代码编辑器）

1. 打开浏览器，访问官网：<https://code.visualstudio.com/>
2. 点蓝色大按钮 **Download for Windows**（Mac 就点 Mac 版）
3. 下载完双击安装包，一路点「下一步 / Next」，直到装完
4. 打开 VS Code（桌面会有蓝色图标）

### 3.2 安装 Live Server 插件（让网页跑起来的小工具）

1. 打开 VS Code，看**左边侧栏**，点那个**四个小方块**的图标（扩展 / Extensions）
2. 在搜索框里输入：`Live Server`
3. 找到作者是 **Ritwick Dey** 的那个（图标是个蓝色小闪电），点 **Install / 安装**
4. 等它装完（几秒钟），不用重启

---

## 4. 第一次打开网站

1. 打开 VS Code → 菜单栏 **文件 / File → 打开文件夹 / Open Folder**
2. 选中 `bushangge` 这个文件夹（就是本说明所在的文件夹），点「选择文件夹」
3. 左侧文件列表里能看到 `index.html`、`ar.html`、`pattern.html`、`style.css`、`assets`
4. **右键** 点 `index.html` → 选 **Open with Live Server**
5. 浏览器会自动打开一个地址，类似：
   `http://127.0.0.1:5500/index.html`
6. 看到《布上歌》的介绍页，说明网站已经跑起来了！

之后每次要打开网站，重复第 4 步就行。

**三个页面互相跳转**：介绍页点「开始体验」进 AR 页，点「纹样图谱」进图谱页，各页顶部/底部都有按钮可以回来。

## 5. 为什么不能双击 html 文件打开

**不要**直接双击 `index.html` 用浏览器打开！

那样地址栏显示的是 `file:///C:/Users/.../index.html`，浏览器会**禁止网页使用摄像头**，AR 页面一定打不开，还可能因为路径问题显示混乱。

必须用 **Live Server** 打开（地址是 `http://127.0.0.1:5500/...`）。
这是浏览器的安全规定，不是项目的问题。

## 6. 生成 AR 靶图文件 targets.mind

AR 识别需要一个叫 `targets.mind` 的「靶图文件」，它是把三张纹样卡图片编译成识别数据的产物。
**这一步只要做一次**（纹样卡图片换了才需要重新做）。

### 6.1 用官方在线编译器（推荐，不用装任何东西）

1. 浏览器打开 MindAR 官方编译器：
   **<https://hiukim.github.io/mind-ar-js-doc/tools/compile>**
   （这是一个网页工具，点开就能用。若国内访问很慢，请多等一会儿，或让能访问的同学帮忙）
2. 页面上有虚线框区域，把三张图片**按顺序**拖进去（或点击选择文件）：

   **第 1 个 → card1.png**
   **第 2 个 → card2.png**
   **第 3 个 → card3.png**

   > ⚠️ 顺序极其重要！第 1 个上传的对应「卡一·唱花」，第 2 个对应「卡二·咏情」，第 3 个对应「卡三·收腔」。顺序错了，识别出来会放错歌。
3. 点页面上的 **Compile** 按钮，等进度走完（大约十几秒到一分钟）
4. 点 **Download** 下载编译结果，得到一个 `.mind` 文件（文件名可能是一长串）
5. 把这个文件**重命名**为：`targets.mind`
6. 把 `targets.mind` 放进项目的 `assets` 文件夹里
   （最终路径是 `bushangge/assets/targets.mind`）
7. 回到 Live Server 的网页，刷新 AR 页试试

### 6.2 验证是否成功

打开 AR 页，点「点击屏幕 开始体验」，允许摄像头，然后把摄像头对准打印好的 card1.png：

- 听到唱段一响起、屏幕下方浮现「起·唱花」的歌词 → **成功**
- 如果提示「未找到 assets/targets.mind」→ 文件没放进 `assets`，或名字不对（必须叫 `targets.mind`）
- 如果一直没反应 → 看[常见问题](#12-常见问题)

## 7. 放入音频文件（唱段）

1. 准备好三段音频，格式用 `.mp3`（`.m4a`、`.wav` 也可以，浏览器同样能播）
2. 把它们**重命名**成下面三个名字（一个字母都不能错，全小写）：

   ```
   song_1.mp3    ← 卡一的唱段
   song_2.mp3    ← 卡二的唱段
   song_3.mp3    ← 卡三的唱段
   ```

3. 把三个文件放进 `assets` 文件夹
4. 刷新网页即可生效

> **重要**：文件名必须完全一致（`song_1.mp3`，不是 `song1.mp3`，也不是 `Song_1.MP3`）。
>
> 如果暂时没有音频文件，网站也能打开，只是在识别到卡时弹一句黄色提示「未找到 assets/song_1.mp3……」，歌词照常显示，不会报错。放好文件后提示自动消失。

**想改歌词？** 打开 `ar.html`，用记事本或 VS Code 搜索 `lyrics:`，就能看到三段歌词，直接改字保存即可。

## 8. 放入背景视频（可选）

介绍页支持一段循环静音背景视频：

1. 准备一段 `.mp4` 视频（内容不限，建议是染布、织布或蓝白纹样相关画面）
2. 重命名为 `bg.mp4`，放进 `assets` 文件夹
3. 刷新介绍页即可

**不放也可以**：没有视频时介绍页自动用深靛纯色背景，不影响任何功能。

## 9. 用手机体验

1. 手机和电脑**连同一个 WiFi**
2. 在电脑上查出自己的 IP 地址：
   - Windows：按 `Win + R`，输入 `cmd` 回车，在黑窗口里输入 `ipconfig` 回车，找 **IPv4 地址**，类似 `192.168.1.105`
   - Mac：系统设置 → 网络 → 已连接的 WiFi → 详细信息，找 IP 地址
3. 手机浏览器（Safari / Chrome / 系统自带浏览器）输入：
   `http://192.168.1.105:5500/ar.html`
   （把 `192.168.1.105` 换成你自己的 IP；端口 5500 是 Live Server 默认端口）
4. 能打开网页，手机体验就通了

### ⚠️ 一个重要限制（请先看，避免困惑）

手机浏览器通过 `http://192.168.x.x` 这种地址访问时，**浏览器不允许网页开启摄像头**（这是浏览器的安全规定，要求 https 或电脑上的 localhost）。所以：

- **电脑上**（`127.0.0.1:5500`）：AR 摄像头正常 ✔
- **手机上**（`http://192.168.x.x:5500`）：会**自动进入 2D 模式**——三张纹样卡排成宫格，点哪张就播哪段歌、显示对应歌词，完整体验作品内容 ✔
- **手机上真 AR**：请看下一节，把网站发布到 GitHub Pages（免费、自带 https），手机打开那个网址就能开摄像头扫卡了

> 小技巧：如果你只是想验证「手机能访问、功能正常」，2D 模式已经足够演示；比赛演示建议用 GitHub Pages 的网址，评委用任何手机打开都是 https，AR 直接可用。

## 10. 发布到互联网（GitHub Pages，免费）

GitHub Pages 免费、自带 HTTPS，手机打开即用 AR。第一次操作约 15 分钟。

1. 注册 GitHub 账号：<https://github.com>（点 Sign up，用邮箱注册）
2. 登录后，点右上角 **+** → **New repository**
   - Repository name 填：`bushangge`
   - 选 **Public**
   - 其它都不勾，点 **Create repository**
3. 建好后会跳到「Quick setup」页面。点顶部菜单 **Add file** → **Upload files**（上传已有文件）
4. 把 `bushangge` 文件夹里的**所有内容**拖进上传框：

   - 根目录 5 个文件：index.html、ar.html、pattern.html、style.css、README.md
   - **`film.mp4`**（主页的作品短片，别漏掉）
   - `assets` 整个文件夹

5. 等上传完（视频和三张卡图较大，可能要几分钟），点 **Commit changes**
6. 点仓库的 **Settings（设置）** → 左边菜单 **Pages**
   - Branch 一项选 `main`，文件夹选 `/ (root)`，点 **Save**
7. 等 1~2 分钟，刷新这个页面，顶部会出现你的网址，类似：
   `https://你的用户名.github.io/bushangge/`
8. 手机浏览器打开 `https://你的用户名.github.io/bushangge/ar.html` → 点开始体验 → 允许摄像头 → 扫描纹样卡

> **`film.mp4` 已压缩到约 15MB**（原始素材 77MB 另存为 `D:\学习\青\film-master.mp4`，在项目外）。**GitHub 网页上传的单文件上限是 25MB**，超了会报 "Yowza, that's a big file"，所以重新导出短片后记得再压一次。有 ffmpeg 的话执行：
>
> ```
> ffmpeg -i film.mp4 -c:v libx264 -crf 26 -preset slow -vf scale=1280:-2 -c:a aac -b:a 96k -movflags +faststart film-new.mp4
> ```
>
> 没有 ffmpeg 就用 HandBrake（免费），目标大小设 15MB。`-movflags +faststart` 那个参数一定要加，它让视频一边下载一边播，不用等下完。压完把文件名改回 `film.mp4` 覆盖原文件，网页不用改。

> `assets` 里那三张 8MB 的 `card1/2/3.png` **网页本身不加载**（网页显示的是 `card1/2/3.jpg`），它们是打印给摄像头扫的靶图源，不影响手机打开速度。想让仓库小一点可以压到 1024×1024，但压完必须重新生成 `targets.mind`，否则识别可能对不上。

## 11. 微信里打不开摄像头怎么办

微信内置浏览器对摄像头支持不稳定（尤其是安卓），可能出现点了没反应、黑屏等情况。

**解决办法**：点微信右上角 **···** → 选 **「在浏览器中打开」**（Safari / Chrome / 系统浏览器都可以），就能正常使用。

如果只是演示给评委看，建议直接用系统浏览器打开，最稳。

## 12. 常见问题

**Q：点了「点击屏幕 开始体验」，摄像头是黑的 / 一直「正在开启摄像头…」**
- 先确认浏览器**允许**了摄像头权限（地址栏左边有个小锁或摄像头图标，看是否被拒绝，拒绝了就改成允许）
- 再确认是用 Live Server 打开的（地址是 http://127.0.0.1:5500 或 https 开头）
- 微信里打不开就换系统浏览器
- 都不行就点右上角「2D 模式」，照样能听歌看词

**Q：提示「AR 组件未能从网络加载」**
- AR 的两个识别组件（A-Frame、MindAR）是联网加载的，打开 AR 页时需要能上网
- 网络断了或太慢会自动转成 2D 模式（不影响听歌看词）；恢复网络后刷新页面即可重试
- 代码里给每个组件准备了 3 个下载地址自动切换，一般不用管；如果换过网络还不行，把 `ar.html` 里 `AFRAME_URLS` 和 `MINDAR_URLS` 两个列表发给懂技术的同学帮你换成能访问的镜像

**Q：提示「未找到 assets/targets.mind」**
- 说明靶图文件没放进 `assets` 文件夹，或名字不对
- 必须是：`bushangge/assets/targets.mind`（小写、后缀 .mind）

**Q：扫卡没反应，歌词不出来**
- 打印的图案太小、反光、太暗都会影响识别：换 A4 彩印、开灯、正对着扫
- 确认生成 targets.mind 时上传的三张图就是现在 assets 里的 card1/2/3.png（图换了要重新编译）
- 手机镜头离卡 20~40 厘米，稍微停稳一两秒

**Q：提示「未找到 assets/song_1.mp3」**
- 音频文件没放进 assets，或文件名不对，见第 7 节
- 不放也能演示（歌词照常显示），放了自动有声音

**Q：识别到卡了，有歌词但没声音**
- 手机可能是静音键拨到了静音（iPhone 左侧）
- 浏览器音量、系统音量调大
- 点一下屏幕后再试（iOS 偶尔要一次点击才出声）

**Q：想改文案 / 歌词 / 页脚的赛事信息**
- 用 VS Code 打开对应的 html 文件，找到那句中文直接改，保存后刷新网页
- 样式（颜色、字号）在 `style.css` 顶部有中文注释的变量可改

**Q：页面样式乱了 / 图片不显示**
- 确认没有改动文件位置；`assets` 文件夹必须和三个 html 文件在同一层

## 13. 文件结构一览

    ├── card3.jpg     纹样卡三小图
    ├── card1.png     纹样卡一大图（打印给摄像头扫；也是 targets.mind 的编译源）

    ├── card3.png     纹样卡三大图
    ├── targets.mind  AR 靶图文件（按第 6 节生成；图换了要重新生成）
    ├── song_1.mp3    唱段一（按第 7 节命名）
    ├── song_2.mp3    唱段二
    ├── song_3.mp3    唱段三
    ├── film-poster.jpg  短片封面图
    └── bg.mp4        介绍页背景视频
```
